Step 1 · Trigger

Add a company

You add a company once. A scheduler then re-runs the full pipeline for it every 24 hours, automatically — no manual step after that.

Step 2 · Collect  collect only open-source search

8 workers fetch data

Each worker pulls from one source and saves the raw page. Workers don't parse anything — they just download. They don't need to know the 103 fields; the extractor (next step) reads every page against all fields.

Search runs on SearXNG, a self-hosted open-source metasearch engine (aggregates Google, Bing, DuckDuckGo, Startpage, Qwant). No API key, no quota, no rate limits — it runs as a container in our own stack.

Step 3 · Extract  parse only

Extract facts from each page

The model reads each page against all 103 schema fields and returns only facts stated in the text — each with a confidence score and the source quote. Fields not found in the text stay empty.

Step 4 · Validate  LLM-as-a-Verifier + source tiers

Mark each fact verified or not

Better sources need fewer confirmations to be marked verified. When two sources disagree, a verifier based on arXiv:2607.05391 (Stanford / UC Berkeley) scores the pair on four separate criteria — same entity · same period · same unit · same value — using continuous confidence scores read from the model's token probabilities, not a yes/no answer. The weakest criterion caps agreement, so a mismatch on entity or period alone blocks a false merge. Genuine conflicts go to manual review; nothing is guessed.

Step 5 · Store

Store in the database

Each fact is stored with its source URL, confidence, and version history — append-only, so old values are kept, not overwritten. Raw documents go to object storage and get indexed for search.

Step 5b · Discover  the schema grows from evidence

Find fields the form doesn't have yet

An analysis agent re-reads everything collected and proposes new columns the 103-field form is missing — each with a rationale, an observed example and a source. Proposals that recur across companies (or score high confidence) are promoted into the real schema, and because the extractor reads its field list from the database at run time, the next pass fills the new columns for every company automatically. See Discoveries.

Step 6 · Serve

How the team uses it

💬 Telegram agent (2-way)

  1. Analyst messages the bot (sandboxed OpenClaw agent, allowlisted IDs only)
  2. Asking? → agent reads the database over a read-only API → replies with facts + citations
  3. Filing a founder call? → agent drops the raw transcript into an inbox (its only write)
  4. The trusted pipeline extracts it → confidential fields (revenue, cap table, ESOP) appear — never scraped

🖥 Dashboard & Search

  1. Company profile = verified facts only; unverified + conflicted live on a separate Needs review tab for that company
  2. Conflict queue — keep / reject in one click
  3. Extraction trace — every field's journey (Companies → trace view)
  4. Discoveries — proposed new columns beyond the 103
  5. Semantic search — plain-language, across every document
Core rule: workers collect · the model parses · the database validates · every fact has a source. The model is never the source of truth — the database is.
